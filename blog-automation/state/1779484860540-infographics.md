## セクション1: Notionで手順書を作る際に直面する3つの課題

```
Notionで手順書作成時のスクリーンショット撮影課題のインフォグラフィックを作成してください。

**タイトル案：** Notionで手順書を作る際に直面するスクリーンショット撮影の課題

**主要ポイント：**
1. 毎日1～2時間がスクリーンショット撮影だけに費やされている
2. 1つの手順書に20～30枚、多い場合は60回以上の撮影が必要
3. 具体例：経理部門の請求書処理（30ステップ）では30～60回の撮影・撮り直し作業が発生
4. 撮影後のファイル管理が困難（自動採番ファイル名から用途が特定できない）
5. 本来は他業務に使える時間が毎日消費される機会損失

**レイアウト種別：** 数字インフォグラフィック

**補足：** 時間（1～2時間）、枚数（20～30枚、60回以上）、ステップ数（30ステップ）といった具体的な数字を視覚的に強調し、スクリーンショット撮影がいかに業務を圧迫しているかを直感的に理解できるデザインにしてください。
```

## セクション2: なぜスクリーンショット管理は属人化するのか？手順書完成を遅延させる根本原因

```
手順書作成の属人化がもたらす問題と解決策のインフォグラフィックを作成してください。

**セクション内容の整理：**

このセクションでは、手順書作成が特定の人に依存する「属人化」がもたらす問題と、その解決策を説明しています。

**主要ポイント：**
1. スタイル統一の欠如 — 統一されていない手順書は、「誰が読んでも同じように実行できる」という目的を果たさない
2. 作業負担の一極集中 — 手順書作成に慣れた担当者1人に仕事が集中し、その人の能力と時間に依存する状態に
3. リスク顕在化 — その担当者が休暇・異動・退職する場合、手順書整備は一気に止まり、モチベーションも低下
4. 解決策：標準化 — 「誰でも同じように作れる状態」を整えることで、チーム全体で手順書作成に参加でき、継続性が生まれる

**レイアウト種別**：横並び比較表（属人化状態 vs 標準化状態）

**補足**：左右で対比させて、標準化の重要性を視覚的に強調してください。アイコンやカラーリングで問題と解決策を区別し、組織全体への影響を表現してください。
```

## セクション3: Notionで効率的な手順書を作るための基本フォーマット

```
Notionの手順書テンプレート構造のインフォグラフィックを作成してください。

フロー図形式で、Notionで効率的な手順書を作るための6つの基本ブロックを上から下へ順に表示してください。

【表示内容】
① タイトル：作業内容を具体的に明記（例：「〇〇申請フロー」）
② 概要・目的：手順書の必要性と効果を2〜3文で簡潔に説明
③ 対象者・前提条件：ユーザーの条件を明記（例：「アカウント保有者向け」）
④ ステップ本文：番号付きリスト＋スクリーンショット配置
⑤ 注意事項・よくある質問：ミス防止と問い合わせ軽減のポイント
⑥ 更新履歴・担当者情報：最終更新日と作成者を記録

【レイアウト指示】
- 各ブロックを矢印で上下に繋いだフロー図
- ブロックには要素の名前と2〜3語の説明を含める
- 色分けやアイコンで各ステップを視覚的に区別
```

## セクション4: スクリーンショット管理を完全自動化する——Chrome拡張の実装ガイド

```
従来方法とChrome Manual Makerの比較インフォグラフィックを作成してください。

スクリーンショットの撮影・注釈・Notion保存という3つの工程が、Notion手順書作成の最大のボトルネック。従来は複数ツール（撮影ツール→画像編集ソフト→Notion）を行き来しながら作業し、1ステップあたり10～15分、全体で2～3時間かかっていました。Chrome Manual Makerを使用すると、この3つの工程を一つの画面で完結でき、1ステップあたり1～2分、全体で15～20分に短縮できます。

【タイトル案】
「スクリーンショット自動化で時短」「2時間の作業が15分に」「Chrome拡張で実現する効率化」

【ポイント】
1. 従来方法の3ステップ：撮影（別ツール）→注釈（画像編集ソフト）→保存（ドラッグ&ドロップ）、1回10～15分、全体2～3時間
2. Chrome Manual Maker使用時：拡張機能アイコンクリック→その場で注釈→ボタンで自動保存、1回1～2分、全体15～20分
3. 削減効果：85～90%の時間短縮、複数アプリの行き来がゼロ、統一インターフェースで直感的操作
4. メリット：ストレス解消、生産性向上、手順書作成に集中可能

【レイアウト種別】
横並び比較表（左列：従来方法、右列：Chrome Manual Maker。各行に処理内容と所要時間を記載。最下行に合計時間を強調表示）

【補足】
最下行「合計時間」で2～3時間→15～20分を大きく表示。赤X（非効率）vs 緑チェック（効率的）でビジュアル強調。アプリ切り替え「0回」という点も視覚的に表現。
```

## セクション5: Notionで手順書を作る際のよくある質問と解決策

```
「Notionの複数人での手順書作成における権限管理と進捗管理」のインフォグラフィックを作成してください。

Notionで複数人が手順書を同時に作成する際、権限管理とステータス管理が重要です。権限は4段階（フルアクセス・編集可能・コメント可能・閲覧のみ）に分かれており、各段階で操作範囲が異なります。実例として5名のチームで10本の手順書を分担する場合、「手順書一覧」データベースに担当者名とステータスプロパティを設定し、ステータスを「未着手」「作成中」「レビュー待ち」「完成」の4段階で管理します。ボードビュー（カンバン方式）で進捗を可視化でき、複数人の同時編集もリアルタイムで反映されます。ただし同じブロックの同時編集による競合を避けるため、担当セクションの事前割り当てが必須です。

タイトル案：「Notion権限管理4段階と進捗状況の管理」
ポイント：（1）権限4段階の操作範囲の違い（2）ステータス4段階のフロー（3）ボードビューでの進捗可視化（4）複数人同時編集時の競合対策
レイアウト種別：横並び比較表
補足：実践的な例（5名チーム・10本の手順書）を視覚的に表現し、権限の操作可否を一目で比較できる表形式を推奨します。
```

## セクション6: 今日から実践できる！Notionで手順書を完成させるための実装ロードマップ

```
Notionで手順書を完成させるための実装ロードマップのインフォグラフィックを作成してください。

【セクション内容の整理】
ユーザーが「基本フォーマット」と「スクリーンショット自動化」の知識を活かして、段階的に手順書完成へ進むための時間軸別アクションプランです。「小さく確実に動き出す」ことの重要性と実行の心理的ハードルを下げることを重視しています。

【時間軸別アクション】
・今日のアクション（15～20分）
  ① Notionにテンプレートページを作成
  ② 業務を1つ選定（日常業務や引き継ぎ業務が最適）
  ③ Chrome Manual Makerをインストール・連携設定

・今週のアクション（1～2時間）
  → 最初の手順書を完成させる（「見せられる状態」が目標）

【作成指示】
- インフォグラフィック種別：タイムライン（上から下、または左から右で時間経過を視覚化）
- タイトル案：「Notion手順書完成ロードマップ」
- 所要時間と各ステップの具体的アクションを明記
- 各段階をカラーで区分けし、進行イメージを強調
- チェックマーク・時計・矢印アイコンで段階的進行を表現
- 最終ゴール（完成した手順書）をビジュアル・ターゲットとして表示
```
